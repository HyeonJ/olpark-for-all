# 《모두의 올팍》 모바일 디자인 리뷰

> 평가 대상: 첨부한 요약·지도 화면과 원본 HTML/CSS/JS, 시설·주차·지도 데이터. 기준 뷰포트 412px. 확정 로고는 변경하지 않는다.

## 총평

공공데이터를 신중하게 다루는 태도는 강점이다. 특히 출처 불일치, 실시간 대여 정보 부재, 주차대수와 잔여면 수의 구별은 출품작의 신뢰 자산이다. 그러나 현재 화면은 정보를 순서대로 쌓은 조회 도구에 가깝다. 심사위원이 첫 화면에서 **“누구와 언제 가고, 그래서 무엇을 준비하면 되는가”**를 한 번에 읽기 어렵다.

공모전 관점의 핵심 과제는 더 많은 장식이 아니다. **판단 → 근거 → 준비 행동 → 현장 위치**의 순서를 분명히 하고, 데이터의 한계를 각 판단에 붙여주는 것이다. 평가는 제공된 화면에 대한 디자인 판단이며 실제 심사 배점표를 가정하지 않았다.

## P0 · 첫 화면에서 서비스 가치가 드러나지 않는다

### 1. 입력 위계가 결과 위계를 압도한다

- 현재 상단은 브랜드·탭, 동행자 칩 두 줄, 날짜·시간, 공휴일 체크로 약 290px를 쓴다. 가장 중요한 답변은 그 아래에서 시작한다.
- ‘시각장애’만 두 번째 줄에 남아 선택지 사이의 균형이 깨진다. 날짜는 브라우저 기본 영문 숫자형으로 보여 한국어 서비스의 완성도를 낮춘다.
- 첫 화면을 보는 심사위원은 방문 준비 서비스보다 조건 설정 폼을 먼저 접한다.
- **개선:** 결과 상태에서는 날짜·시간·동행자를 한 줄의 방문 조건으로 압축한다. 조건을 다시 확인하는 영역은 펼침 구조로 분리한다. 결과 제목에 ‘서울 올림픽공원 / 출발 전 준비’라는 목적을 붙인다. 실제 서비스 적용 시에는 펼친 영역에서 기존 조건 편집 기능을 유지한다.

### 2. 핵심 답변과 해야 할 행동이 분리되어 있다

- ‘15시보다 한산한 편이에요’는 비교 대상 15시를 먼저 이해해야 읽힌다. 문장 끝이 현재·미래의 방문 상황처럼 들릴 여지도 있다.
- ‘61% 정도만’은 읽으면서 계산해야 하고, 인원 혼잡과 차량 혼잡을 혼동할 수 있다.
- 휠체어 대여는 사전 문의가 필요한데 긴 시설 목록 안에 섞여 있다. 첫 답변을 읽어도 다음 행동이 명확하지 않다.
- **개선:** ‘토요일 10시, 오후보다 한산했어요’처럼 방문 시각과 과거 시제를 함께 제시한다. 바로 아래에서 ‘작년 같은 계절의 주말·휴일’, ‘차량 기준’을 밝힌다. ‘대여 가능 여부 전화 확인’을 첫 준비 행동으로 올린다.

### 3. 통합 데이터가 확정 사실처럼 읽힐 수 있다

- 현재 장애인 주차 항목의 첫 문장은 ‘140칸 있음’이고, 값의 의미가 다르다는 설명은 뒤에 있다. 작은 ‘출처마다 다름’ 배지만으로는 첫 문장의 확신을 상쇄하기 어렵다.
- 공식 무장애 자료에는 화장실의 정확한 위치가 없지만 지도에는 WC가 표시된다. OSM 자료라는 설명을 펼치지 않으면 공식 기관이 검증한 위치로 읽힐 수 있다.
- 지도 장소 상세에 공원 전체 차량 흐름을 함께 두면 그 안내센터 주변의 혼잡도로 오해하기 쉽다.
- **개선:** ‘주차면 수 확인 필요’를 제목으로 쓰고 API ‘장애인 주차장 140칸’ / 웹 ‘주차 개수 140’을 병렬 배치한다. WC 옆·지도 하단에 OSM 등록 위치, 현장 검증 전임을 밝힌다. 차량 흐름은 요약의 공원 전체 근거로 두고 시설 상세에서 뺀다.

## P1 · 실서비스 완성도를 좌우하는 시각 체계

### 4. 타이포그래피: 굵은 요소가 많아 중요한 것이 평평해진다

- 칩, 제목, 숫자, 시설명, 지도 라벨, 전화 버튼이 모두 굵다. ‘1,423대’, ‘1,970대’, ‘공원 안내’의 우선순위가 비슷하게 보인다.
- 핵심 수치와 ‘10시 주차대수 중앙값 · 보통 범위’가 한 문단으로 섞여 단위·분포·대표값의 관계가 잘 보이지 않는다.
- 시설 본문의 긴 줄, 작은 차트 라벨·출처가 공존해 화면 안에서 읽는 속도가 들쭉날쭉하다.
- **개선:** 대표 제목 32~45px, 과거 대표값 48~62px, 섹션 제목 18~28px, 본문 14~16px로 역할을 구분한다. 중앙값과 범위를 별도 줄로 나눈다. 숫자는 같은 글꼴과 자릿수 폭을 쓰고 ‘대’를 작게 붙인다. 작은 보조 글씨에도 대비를 확보한다.

### 5. 색: 초록·파랑·갈색이 각자 강조한다

- 초록은 브랜드·선택·차트, 파랑은 아이콘·링크·지도 핀·필터, 갈색은 상태에 쓰인다. 색 자체보다 채도와 강조 면적이 비슷한 것이 문제다.
- 지도 탭의 큰 파란 필터들이 장소보다 먼저 보이고, 각 시설 아이콘의 파란 배경이 목록 전체를 점묘처럼 분절한다.
- **개선:** 브랜드의 초록을 유지하되 시안별 주 강조색을 한 가지로 제한한다. 주차 ‘보통’은 문자와 점·테두리를 함께 사용한다. 확인 필요 영역은 차분한 황토색 배경과 명시적 문장으로 표현한다. 지도는 저채도 바탕·물·녹지와 대비 높은 핀을 쓴다.
- 텍스트 4.5:1 이상, 핵심 UI 경계·그래픽 3:1 이상을 목표로 한다. 선택·상태·차트 기준은 색 외에도 텍스트·밑줄·마커·점선으로 표현한다.

### 6. 여백과 표면: 모든 정보가 같은 카드다

- 차트·시설·지도·실시간·데이터 한계가 같은 흰색, 유사 반경, 유사 테두리다. 카드의 목적 차이가 약하다.
- 각 카드 안의 본문은 조밀한데 카드 사이에는 여백이 반복된다. 이 때문에 화면이 길면서도 여유롭지 않다.
- **개선:** 핵심 근거는 독립 표면, 시설 준비는 구분선 목록, 불일치는 펼침 주의 영역, 현재 주차는 작은 참고 블록으로 구분한다. 섹션 시작과 항목 사이 여백을 달리해 장면 전환을 만든다. 그림자는 기본값으로 쓰지 않는다.

### 7. 아이콘: 배경 상자보다 의미와 선의 일관성이 필요하다

- 같은 파란 사각형 안의 문·대여·화장실 기호가 작은 크기에서 비슷하게 뭉쳐 보인다. 휠체어 대여 기호도 이름 없이는 즉시 이해하기 어렵다.
- **개선:** 24px 좌표계, 1.7px 선, 같은 끝·모서리 처리로 직접 그린 SVG를 사용한다. 대여는 보관함, 접근은 문, 주차는 P 등 시설 중심 기호로 표현한다. 아이콘만으로 뜻을 전달하지 않고 항상 제목을 병기한다. 동행자의 정체성을 반복하는 휠체어 픽토그램은 사용하지 않는다.

### 8. 차트: 근거로 읽기에는 작고, 읽는 순서가 약하다

- 원본은 120 높이 SVG 안에 곡선·붐빔 기준·선택 마커·시간 라벨을 모두 넣는다. 모바일에서는 선과 숫자가 압축된다.
- 면적 채움이 기준 점선을 일부 덮는 순서이며, 선택한 10시와 최고점 15시를 찾아 시선을 왕복해야 한다.
- ‘그날의 차량 흐름’이라는 제목은 해당 방문 날짜의 예측이나 실제 하루 관측값처럼 들린다.
- **개선:** 제목은 ‘10시의 차량 흐름’ 또는 ‘10시에 도착한다면’으로 바꾸고, 중앙값·분포를 먼저 읽히게 한다. 차트에 선택 시각 라벨과 수직선, ‘붐빔 기준 2,036대’를 직접 표기한다. 도형을 면 → 기준선 → 곡선 → 선택점 순으로 그린다.
- 하루 곡선은 제공된 6~21시 중앙값 16개를 그대로 연결한다. 별도의 불확실성 밴드나 매끈한 임의 보간을 만들지 않는다. 아래에는 ‘15시 2,334대보다 911대 적었어요’ 또는 ‘약 39% 적은 차량’을 문장으로 제공한다.
- ‘보통 범위’는 제공된 사분위 범위이며 예측 오차나 최대·최솟값이 아니다. 출처 펼침에 정의를 둔다. ‘보통’ 상태는 여유 1,243대 이하 / 붐빔 2,036대 이상이라는 별도 분류다.

### 9. 지도: 지형은 크지만 위치를 이해할 단서가 부족하다

- 큰 공원 면과 물길에 비해 핀 글자가 작고, 긴 장소명이 외곽에 붙어 축소 지도에서 뭉친다.
- 선택한 안내센터와 일반 WC의 크기·색 차이가 작다. 지도 아래 시트는 눈에 띄지만 지도에서 무엇을 골랐는지 연결이 약하다.
- 가로 스크롤 필터의 다음 항목이 잘려 보이고, 선택 상태의 큰 파란 면적이 지도를 압도한다.
- **개선:** 원본 공원 경계·물길·시설 좌표를 유지하고 바탕색을 낮춘다. 선택 장소는 더 큰 핀과 흰 테두리, 장소명으로 강조한다. 북쪽 표기, 대여/WC/P 범례, 출처를 붙인다. 상세에는 대여 수량·수유실·전화 확인만 모은다.
- 확인되지 않은 무장애 경로, 도보 소요 시간, 경사 안전도, 출입구별 주차 여유는 그리지 않는다. 지도에 길처럼 보이는 장식 선도 추가하지 않는다.

### 10. 카피: 친근함과 정보 밀도를 함께 조정해야 한다

- ‘어디서 빌리고, 어디서 쉬나’는 방향은 좋지만 구어적 생략과 긴 제목이 섞여 톤이 일정하지 않다.
- ‘있음’, ‘가능’, ‘확인 필요’가 한 문장 안에서 이어져 확정 정보와 미확인 정보가 분리되지 않는다.
- **개선:** 제목은 ‘빌리는 곳, 쉬어갈 곳’, 행동은 ‘출발 전에 전화해요’, 근거는 ‘작년 기록이에요’처럼 역할별로 짧게 쓴다. 시설별로 ‘공식 정보 / 전화 확인 / 위치 참고’를 텍스트로 표시한다.
- 전화 링크는 공원 대표번호임을 밝힌다. 특정 안내센터 직통번호나 대여 보장을 암시하지 않는다.

## P2 · 제출 전 접근성과 사용 상태 점검

- 원본 `tabs__btn` 높이 38px, `pick` 42px, 지도 필터 40px, 공휴일 라벨 최소 높이 32px는 서비스 대상에 비해 작다. 실제 인터랙션은 최소 44×44px, 주요 행동은 48px 이상으로 정리한다.
- 작은 지도 핀을 실제 선택 버튼으로 옮길 때는 시각적 원 크기와 별개로 44px 이상의 히트 영역을 확보하고 겹침을 해결해야 한다. 시안의 지도는 정적 SVG이며 핀 버튼처럼 동작한다고 표시하지 않았다.
- `focus-visible`, 본문 바로가기, 문서 언어, 제목 계층, SVG 설명, 링크 이름을 유지한다. 아이콘은 보조 장식으로 숨기고 텍스트로 의미를 제공한다.
- 명암비는 글자 크기·색 조합별로 확인한다. 연한 녹지·물은 지도 바탕이며, 그 위의 텍스트와 핀은 별도 대비를 확보한다.
- 확대·작은 뷰포트에서 조건 행·차트·시설명이 잘리지 않는지 실기기 검증이 필요하다. 원본의 `text-wrap: balance`만으로 긴 한국어 제목의 줄바꿈을 해결하지 않는다.
- 실제 서비스 적용 시 조건 변경·로딩·오류·실시간 조회 시각·통신 실패·빈 지도 선택 상태를 별도 처리해야 한다. 정적 출품 시안에 성공 상태만 있다고 이 흐름들이 구현되었다고 주장하면 안 된다.
- 심사위원용 ‘경진대회 출품작’ 문구는 푸터로 내린다. 첫 화면은 이용자의 방문 준비에 집중한다.

## 산출물과 검증 범위

- `design-1.html`, `design-2.html`은 각각 CSS·로고·지도 경로·차트가 인라인인 독립 HTML이다. `fetch`, 자바스크립트, 외부 이미지가 없어 파일을 직접 열 수 있다. Pretendard CDN을 읽지 못하면 시스템 한국어 글꼴로 대체된다.
- 각 파일은 **요약 전체 → 화면 구분 표시 → 지도 전체** 순서다. 상단 요약/지도 링크, 지도 진입 링크, 전화 링크, 방문 조건 및 데이터 설명의 펼침을 사용할 수 있다.
- 방문 조건과 지도 필터는 제공된 상태의 고정 시안이다. 필터는 버튼처럼 클릭되지 않으며, 조건 펼침에 고정 상태임을 표시했다. 조건 편집·실시간 API·다른 장소 선택 기능은 구현 범위가 아니다.
- 과거 1,423대 / 범위 1,180~2,198대 / 표본 15일 / 15시 2,334대 / 현재 주차 예시 1,974대를 사용했다. 현재 예시를 실제 조회한 값처럼 보이지 않도록 ‘고정 예시 · 실시간 연결 전’을 표시했다.
- 브라우저 자동 검증을 시도했지만 실행 환경의 소켓 생성 제한(`Operation not permitted`)으로 agent-browser와 직접 Chromium 모두 시작되지 않았다. 따라서 렌더링 스크린샷과 실제 모바일 조작을 확인했다고 주장하지 않는다. 정적 문서 구조·중복 ID·앵커 연결·인라인 자산·주요 수치 일치 여부를 확인했다. 주요 본문·보조문·강조문·반전문 색 조합은 계산상 1안 최소 5.20:1, 2안 최소 4.90:1이었다. 이는 브라우저 기반 접근성 검사나 실기기 검증을 대체하지 않는다.

## 선택 제안

제출용 기본 방향으로는 **1안**을 권한다. 차분한 공공 서비스 톤을 유지하면서 첫 화면에 방문 판단과 전화 확인 행동이 함께 드러나고, 기존 로고의 초록과 자연스럽게 이어진다. 2안은 타이포그래피의 개성과 기억에 남는 인상을 더 중시할 때 적합하다. 두 시안의 구조를 무작정 섞기보다 하나의 정보·표면 체계를 끝까지 유지하는 편이 좋다.

## 시안 1 · 방문 브리핑

초록과 밝은 종이색, 절제된 한 장의 데이터 카드로 신뢰감 있는 공공 서비스의 인상을 만든다.  
방문 조건을 접고 ‘오후보다 한산했던 10시 → 대여 전화 확인 → 근거 차트’ 순서로 판단과 행동을 앞세운다.  
구분선 시설 목록과 낮은 채도의 참고 지도를 연결해, 긴 안내를 차분하게 끝까지 읽을 수 있게 한다.

## 시안 2 · 공원 방문 안내지

아이보리 종이, 짙은 잉크색 구분선, 적갈색 강조와 큰 숫자로 편집된 공원 안내지의 인상을 만든다.  
‘도착 시간 → 출발 전 준비 → 공원 안 시설’의 세 장면을 번호와 타이포그래피로 구분하고 반복 카드를 없앤다.  
로고는 그대로 유지하며, 정보의 정직함은 병렬 출처·과거 시제·명시적 확인 문장으로 전달한다.
