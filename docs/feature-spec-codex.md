**메뉴 2개면 충분하다. 추가 메뉴는 필요 없다.** 심사에서도 기능 수보다 ‘기관 데이터를 써서 방문 전 어떤 판단을 돕는가’가 중요하다. 현재 구성의 약점은 기능 부족보다 **차량 수를 이동 편의로 과해석할 가능성**이다.

[design-3.html](/home/bpx27/projects/olpark-for-all/mockups/codex/design-3.html)을 기준으로 판단했다. 아래 개발 가능성은 **6일·1인 기준 추정**이다.

**1. 반드시 보완할 것**

빠진 **독립 메뉴는 없다.** 기존 화면 안에서 세 가지는 필요하다.

| 보완 | 필요한 이유 | 데이터로 가능한가 | 6일 내 |
|---|---|---|---|
| 결론 바로 아래 공연·행사 확인 링크와 미반영 안내 | 과거 차량 기록만으로 방문일을 판단하는 오류 방지 | 가능. 공식 일정으로 연결 | 가능 |
| 지도와 같은 시설을 제공하는 텍스트 목록 | 시각장애인이 핀 없이도 장소 선택·전화 가능해야 함 | 확보한 시설명·좌표·설명으로 가능 | 가능 |
| 표본 부족·조회 실패·오래된 값 처리 | 조건을 바꾸거나 API가 실패해도 근거 없는 결론을 내면 안 됨 | 가능. 표본 일수·조회 상태로 처리 | 가능 |

접근성은 추가 기능이 아니라 **대상 이용자를 위한 기본 구현 조건**이다.

**2. 요청한 여섯 항목 판정**

- **(a) 공연·행사: 공식 링크로 충분하다.** 결론 아래에 “방문일의 공연·행사는 이 비교에 반영되지 않았습니다”와 ‘공식 일정 확인’을 둔다. 실제로 [공식 홈페이지에는 향후 공연 일정이 있다](https://www.ksponco.or.kr/olympicpark/menu.es?mid=a20301000000). 확보한 API에 미래 데이터가 없다는 뜻이지, 확인할 곳이 없다는 뜻은 아니다. 자동 수집·자체 일정표는 이번에 제외한다.  
  과거 비교는 **권장 이하**다. 결측을 ‘비공연일’로 간주하지 말고, 행사 기록의 완전성이 확인된 경우에만 ‘공연 기록 있음/없음’으로 비교한다. 같은 계절·요일유형으로 나누면 이미 15일인 표본이 더 작아진다. 우선 제출자료에서 분석하고, 화면 추가는 결과가 유용할 때만 한다. “공연이 최대 변수”도 현재 제시된 근거만으로는 **가설**이다.

- **(b) 게이트별 차량 흐름: 제외.** 통과 차량 수로 대기시간·주차 여유·휠체어 접근성을 알 수 없다. 차량이 적은 문이 대여소나 목적지에서 멀 수도 있다. 게이트 번호와 실제 문의 대응을 검증하면 과거 통과량은 계산할 수 있지만, **추천 출입구의 근거는 부족하다.** 새 화면에 넣을 이유가 없다.

- **(c) 날씨: 별도 조건·보정 제외.** 과거 날씨는 방문일 예보가 아니다. 256일을 계절·요일·강수·기온으로 계속 쪼개면 표본도 줄어든다. 필요하면 기존 준비 항목에 외부 예보 링크만 둔다. 날씨별 차량 분석은 제출자료의 보조 분석으로 충분하다.

- **(d) 가족 공유: 권장, 후순위.** 날짜·시각·동행 조건이 복원되는 URL 공유면 충분하다. 링크를 열었을 때 실시간 값은 다시 조회하고, 과거 비교 기준은 표시한다. 이미지 카드·계정·가족 그룹은 제외한다.

- **(e) 접근성: 설정 메뉴보다 기본 동작이 필수.** 화면 낭독용 이름, 선택 상태·결과 변경 안내, 키보드 조작, 초점 이동, 차트 대체 표, 전체 시설 목록을 제공한다. 시안에는 일부가 이미 있다. 큰 글씨 전용 모드는 생략해도 되지만, **브라우저 글자 확대 200%에서 내용·버튼이 잘리면 안 된다.** [W3C 확대 기준](https://www.w3.org/WAI/WCAG21/Understanding/resize-text)에 맞춰 확인하고 실제 휴대전화 화면 낭독으로 주요 과업을 점검한다.

- **(f) 관리자·기관용: 제외.** 기관 운영업무나 사용자가 확인되지 않았다. 심사용 데이터 정제 근거는 문서로 제시하면 된다.

**3. 줄이거나 고칠 것**

- **‘여유·보통·붐빔’ 상태 배지는 삭제 권고.** 전체 관측값의 분위수는 주차장 만차나 보행 혼잡 기준이 아니다. “작년 같은 조건에서 10시는 15시보다 주차 차량이 적었습니다”면 충분하다.
- **OSM `wheelchair=yes`를 곧바로 ‘장애인 화장실’로 단정하지 말 것.** “휠체어 이용 가능으로 등록된 화장실”로 표기한다. 아래쪽 주의문만으로 제목의 확정을 상쇄하기는 어렵다.
- **출처 충돌 수량은 접힌 상세로 유지.** 기본 화면은 ‘위치·전화 확인 행동’에 집중한다. 현재 방향이 맞다.
- **공연장·수유실 필터는 장소별 위치 근거가 있는 것만 제공.** 확인되지 않은 좌표를 채워 넣지 않는다.
- **실시간 주차는 보조 정보로 유지.** 미래 방문일과 무관한 ‘현재 값’임을 밝히고 조회 시각·실패 상태를 표시한다. 시안의 고정 예시는 실제 서비스에서 제거한다.
- 공휴일은 날짜로 자동 판정한다. 별도 사용자 선택은 불필요하다.
